# plotter: saved views Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Named, saved chart views (icon, short name, Nav/Fish/None chart, per-slot continuous size or a cell layout), picked from favourite tabs or a Home page, edited in place on the live view, with the tab bar auto-hiding so the chart gets the whole width.

**Architecture:** Pure C++ in `plottercore` does the data and the maths: view JSON and storage (`Views`, `ViewsModel` over a new `views` table, schema 1.1.0), the cell tiling generator (`Tilings`), the slot size clamp (`SlotClamp`). The live page always renders one `ViewDraft` (a QObject with slot and cell list models carrying formatted values); showing a view loads the draft, the editor mutates the draft, Done saves it through `ViewsModel`, Cancel reloads it. Pages are full window width with a `rightInset` for the tab bar, which is an overlay that slides off the right edge, so nothing on a page moves when it hides.

**Tech Stack:** As the parent plan (C++23, Qt 6.8, QML, Qt Test and QuickTest offscreen) plus Qt Svg (LGPL-3, dynamic) for the bundled Tabler icons (MIT).

**Spec:** `docs/superpowers/specs/2026-10-31-plotter-views-design.md` (addendum; parent `docs/superpowers/specs/2026-10-29-plotter-design.md`, parent plan `docs/superpowers/plans/2026-10-29-plotter.md`). Spec sections 6.7 and 6.12 still say 60 shapes; 6.4 corrected the count to 72 after the builder check, and 72 is what this plan builds.

**Process:** branch `plotter-views` (from `main` 4196583), one follow-up PR opened after Task 1 as a draft; reviewers post on the PR per task; rulings go to `.superpowers/sdd/2026-10-29-plotter/progress.md`. Task 18 of the parent (Pi measurement) stays its own PR.

## Global Constraints

- Everything in the parent plan's Global Constraints (no GPL, Qt dynamic, `-DCM_BUILD_PLOTTER=ON` only, Qt 6.5 minimum, 12 mm controls, 15 mm tabs, `--` for stale, WAL + FULL, TDD, no em-dash) still holds.
- Slot size clamped to the room left (R51): a slot never overflows the page or its neighbours; a stored value above the ceiling is clamped at draw time, never rewritten.
- Slot size: `sizeMm` digit height, one decimal, floor 6 mm; old names map small 8, medium 14, large 25.
- Name 1 to 24 characters, short name 1 to 6, both through the on-screen keyboard only (our own QML keyboard; Qt Virtual Keyboard is GPL).
- Cell layouts: every rectangular tiling of the 2x2, 2x3 and 3x2 grids, 72 distinct shapes, 1 to 6 cells, generated by code, stored by key.
- Tab bar: favourite tabs 15 mm square (icon over short name), then the house tab, a 2 mm gap, Lock, palette; favourites beyond `favouriteCapacity` are plain views; the bar auto-hides on views after `tabBarHideS` (default 8, Off = 0) and any plain tap brings it back; nothing on the page moves when it hides.
- Shipped views on first run, all favourites, in order: Navigation (nav, TL Depth 25 mm, TR SOG 25 mm), Fishing (fish, same slots), Big numbers (none, two cells side by side, Depth and SOG).
- Icons: a bundled subset of Tabler Icons (MIT) as SVG, listed in `THIRD_PARTY_NOTICES`, drawn in the palette's text colour (night stays red on black).
- Schema 1.1.0: table `views(id, ord, json)`; migration seeds from a plan 3 database's `slots` and `bigNumbers` rows (then deletes those rows and `chartMode`, `touchLockTimeoutS`), or the shipped three on a fresh file. Unknown JSON keys in a view survive a save (R34).
- Removed: the Navigation/Fishing mode button, the `chartMode`, `touchLockTimeoutS`, `slots`, `bigNumbers` settings, the idle auto-lock, the Settings "Edit overlays" row, the Numbers page cell picker, the `--mode` and `--slots` dev options.
- Every UI task runs its QML tests at both 1024x600 and 1280x800 and saves screenshots at both sizes where the task says.

## Review Focus

1. **A Fish view with no bathy pack installed.** Expected: the view shows the Nav chart with a "No fishing chart installed" chip, never blocks or crashes. Task 6.
2. **A stored `sizeMm` the panel cannot hold** (a view saved at 1280x800 opened at 1024x600, or a hand-edited 90 mm). Expected: drawn clamped, the stored value untouched after reopen. Tasks 4 and 6.
3. **A views row written by a newer app or by hand** (layout key that is not a tiling, unknown chart, icon or field name, extra keys). Expected: those fields take their defaults, the extra keys survive the next save, the app starts. Task 2.
4. **Deleting the view being shown, or the last view.** Expected: the shown view moves to a neighbour; the last view cannot be deleted (Home menu and Setup sheet both refuse). Tasks 4, 7, 11.
5. **A name that gives an empty or over-long short name** (all spaces, a duplicate of a 24-character name). Expected: short name never empty ("View") and never over 6 characters; a tab never grows past 15 mm. Tasks 4 and 7.

### Task 1: Cell tiling generator

**Files:**

- Modify: `plotter/CMakeLists.txt` (plottercore source, `plotter_add_test(tst_tilings ...)`)

**Interfaces:**
- Produces, in `Tilings.h`:
  - `struct CellRect { int col, row, colSpan, rowSpan; bool operator==(const CellRect&) const = default; };`
  - `struct Layout { int cols, rows; QList<CellRect> cells; bool operator==(const Layout&) const = default; };` cells in reading order (by row, then col, of the top-left corner).
  - `QString layoutKey(const Layout&)`: `"<cols>x<rows>:<col>,<row>,<colSpan>,<rowSpan>;..."`, cells in reading order, for example `2x3:0,0,2,1;0,1,1,2;1,1,1,2`.

  - `bool sameShape(const Layout&, const Layout&)`: equal as fractions of their grids (the 2x2 two-column split equals the 2x3 one).
  - `const QList<Layout>& allLayouts()`: the 72 distinct shapes, order: cell count, then grid (2x2, 2x3, 3x2), then key. Generated per grid (every rectangle whose top-left is the first uncovered cell in reading order, recursively), then deduplicated by `sameShape` keeping the first grid's version.
  - `QString canonicalKey(const Layout&)`: the key of the `allLayouts()` entry with the same shape (empty when none).
  - `QVariantList layoutRects(const Layout&)`: `[{x, y, w, h}]` as fractions 0 to 1, cell order.
  - `QList<Layout> tilings(int cols, int rows)`: one grid's complete list before deduplication (exposed for the count test).

### Task 3: Slot size clamp

**Files:**
- Create: `plotter/src/core/SlotClamp.h`, `plotter/src/core/SlotClamp.cpp`, `plotter/tests/tst_slotclamp.cpp`
- Modify: `plotter/CMakeLists.txt`

**Interfaces:**
- Consumes: `Slots.h` (`SlotId`), `Views.h` (`kMinSizeMm`).
- Produces, in `SlotClamp.h`:
  - `struct SlotBox { SlotId id; bool takesRoom; double sizeMm; double fixedWMm, wPerMm, fixedHMm, hPerMm; };` a slot's box is `fixed + per * sizeMm` in each axis (the QML page measures `fixed` and `per` from its layout and the field's `widestSample`); `takesRoom` is on, or any slot in edit mode.
  - `struct ClampSpace { double pageWMm, pageHMm; double marginMm = 1.5; double gutterMm = 2; };` the page width without the tab bar strip and the height above the notice line, at the bar-shown width.
  - `double boxWidthMm(const SlotBox&, double sizeMm)`, `double boxHeightMm(const SlotBox&, double sizeMm)`.
  - `double clampSizeMm(double wanted, double maxMm)`: rounded to 0.1, at least `kMinSizeMm`, at most `max(maxMm, kMinSizeMm)`.
  - `double maxSizeMm(SlotId id, const QList<SlotBox>& boxes, const ClampSpace&)`: the largest 0.1 mm step at which `id`'s box fits, the other boxes at their given `sizeMm`: Top and Bottom height at most `pageHMm / 3`; Left and Right width at most `pageWMm / 3`; the corner area is `pageWMm - 2 margin - Left and Right widths (those that take room)` by `pageHMm - 2 margin - Top and Bottom heights (that take room)`; a corner's width plus the gutter plus its row partner's current width (TL with TR, BL with BR, when that partner takes room) fits the area's width, and its height plus the gutter plus its column partner's current height (TL with BL, TR with BR) fits the area's height. Never below `kMinSizeMm`.
  - `QList<double> drawnSizesMm(const QList<SlotBox>& boxes, const ClampSpace&)`: the size to draw each slot at, in the boxes' order. Bars first (Top, Bottom, Left, Right, each clamped alone), which fixes the corner area; then each corner's drawn size is its stored size times the smallest fit factor (at most 1) over the constraints it belongs to: alone in the area, its row pair (`(fixedA + perA*k*a) + gutter + (fixedB + perB*k*b) <= areaW` when the partner takes room), its column pair likewise against the area height; floored to 0.1 and through `clampSizeMm`. Two 40 mm corners in a 200 mm area draw at 33.2 each (spec 6.3's worked number). Deterministic; nothing is written back. (Ruling R64, 2026-10-31: replaced the earlier order-based pass, which starved the first corner.)
  - Both functions also bound a Top or Bottom bar's width to `pageWMm` and a Left or Right bar's height to `pageHMm` (ruling R65), so a wide one-line position banner never leaves the page.
