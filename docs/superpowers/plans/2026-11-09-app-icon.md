# App Icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the owner's Z3 icon with the plotter and have the installer register it, so GNOME shows it in the taskbar, Alt-Tab, app grid and Activities search.

**Architecture:** The SVG is committed under `plotter/assets/`, installed by CMake into the bundle at `share/icons/hicolor/scalable/apps/cheekyplotter.svg`, and the plotter names its desktop file so GNOME matches the window. The installer copies the icon from the set being installed into the system hicolor theme, writes a system app-menu entry, and adds `Icon=`/`StartupWMClass=` to the autostart entry.

**Tech Stack:** CMake, Qt 6 (C++), bash (installer, bundle script), Python unittest (installer tests with shims under `CM_ROOT`), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-09-app-icon-design.md`

## Global Constraints

- Artwork: copy `~/cheekymarine-icon-z3/cheekymarine-icon-z3.svg` byte for byte to `plotter/assets/cheekyplotter.svg`. Never edit the art. Never touch `~/cheekymarine-icon/`.
- Icon name everywhere: `cheekyplotter` (desktop file `cheekyplotter.desktop`, `Icon=cheekyplotter`, `StartupWMClass=cheekyplotter`, `setDesktopFileName("cheekyplotter")`).
- Bundle path: `share/icons/hicolor/scalable/apps/cheekyplotter.svg`. System path: `/usr/share/icons/hicolor/scalable/apps/cheekyplotter.svg`, mode 644.
- App-menu entry: `/usr/share/applications/cheekyplotter.desktop`, mode 644, exact text in Task 2.
- No Qt `setWindowIcon`, no PNG sizes, no single-instance logic, no version bump, no release.
- No local plotter builds: the plotter and bundle are verified by CI on the PR (`plotter-ci.yml`, `plotter-release.yml` bundle job).
- Every installer system path goes through `p`. No em-dashes anywhere. US English.
- Commit messages end with the session attribution lines.

## Review Focus

1. A set whose plotter bundle has no icon (today's 0.2.1) on a fresh machine: install succeeds, no icon file, no icon-cache call, menu entry still written. Test: `test_set_without_icon_installs` (Task 2).
2. Installing an older set with no icon after one with an icon (what an owner downgrade does): the installed icon stays. Test: `test_icon_kept_when_set_has_none` (Task 2).
3. Icon file in the tarball with a tight mode (0600): installed copy is still 644 so GNOME (running as the user) can read it. Test: `test_icon_installed_from_set` uses mode 0o600 (Task 2).
4. Fresh system with no `/usr/share/icons/hicolor/scalable/apps` or `/usr/share/applications`: both created, 755. Test: `test_icon_installed_from_set` and `test_menu_entry` assert dir modes (Task 2).
5. Repeated installs leave no `.tmp` files in either system dir. Test: `test_no_tmp_left` (Task 2).
