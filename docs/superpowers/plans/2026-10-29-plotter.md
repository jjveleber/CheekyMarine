# plotter (Qt chart plotter app) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The helm chart plotter app: a Qt 6 Quick app that draws the installed chart and bathy packs with MapLibre Native, puts the own boat, track and AIS targets on the chart, shows Garmin-style data slots and a big numbers page from n2kd's live data, and survives power cuts, on the dev machine and on a Pi 5 under EGLFS.

**Architecture:** One CMake subproject `plotter/` with a static library `plottercore` (all logic, Qt Core/Network/Sql/Gui only, fully unit tested with Qt Test) and the app executable `cheekyplotter` (QML pages plus a thin MapLibre adapter). Every MapLibre call goes through one abstract interface, `ChartMap`, so the chart logic (`ChartController`) is tested against a fake and only the adapter depends on the API the spike chooses. Data enters through `N2kClient` (n2kd socket), packs through `PackCatalog` and `StyleLoader`, persistent state through `Store` (SQLite with versioned migrations).

**Tech Stack:** C++23 (repo standard), Qt 6.8 LTS (Core, Gui, Network, Sql with the SQLite driver, Quick, QuickControls2, Test, QuickTest; Location and Positioning only if the spike picks the Qt Location path), maplibre-native-qt built from a pinned commit, CMake 3.25+, Ninja, Python 3 stdlib for the synthetic N2K generator, n2kd from this repo for replay.

**Spec:** `docs/superpowers/specs/2026-10-29-plotter-design.md` (parent: `docs/superpowers/specs/2026-10-28-cheekymarine-design.md` sections 2, 4, 6.2, 6.5, 6.9, 8, 9; contracts: root `README.md` "JSON messages", `chartpack/README.md` "Pack contract").

## Global Constraints

- No GPL code or assets. Qt 6 (LGPL-3) and maplibre-native-qt's QML bindings (LGPL-3 option) are linked dynamically, never statically. maplibre-native-qt core is BSD-2. Every new dependency's licence is checked before it is added and listed in `THIRD_PARTY_NOTICES`.
- Plotter is built only with `-DCM_BUILD_PLOTTER=ON`; default OFF, so the existing `ci.yml` build job, `build-release.yml` and `release.yml` are unchanged.
- Qt 6.5 minimum (`find_package(Qt6 6.5 ...)`); dev and CI use Qt 6.8.3 from aqtinstall in `~/Qt`; the Pi uses Raspberry Pi OS trixie apt Qt 6.8.2.
- n2kd contract: socket default `/run/cheekymarine/n2k.sock`; first line `{"type":"hello","schema":1,"version":"X.Y.Z"}`; vessel values in SI (m/s, radians, metres, kelvin, epoch seconds); `null` means stale or unknown; unknown keys ignored; a final line without a newline after a disconnect is discarded.
- Pack contract: rewrite only source URLs (`mbtiles://enc|bathy|dem`), `sprite` (`pack://sprites/<name>`) and `glyphs` (`pack://glyphs/{fontstack}/{range}.pbf`); change depth thresholds only in the filters of layers listed in `metadata.cheekymarine.depths.layers`; refuse a pack whose `schema` is not 1. Fish styles use `enc`, `bathy` and `dem`.
- Depth defaults: shallow 6 ft, safety 10 ft, deep 30 ft (1.8288, 3.048, 9.144 m). Valid settings: shallow < safety < deep, each 0.5 to 60 m.
- Sizes: every tappable control at least 12 mm; tab bar tabs at least 15 mm; slot digit heights small 8 mm, medium 14 mm, large 25 mm; physical size from setting `panel_diagonal_in` (default 10.1, range 7 to 15).
- A stale or missing value renders as `--`. Never the last good number.
- SQLite: `journal_mode=WAL`, `synchronous=FULL`. Schema version 1.0.0 in plan 3.
- App version: `set(PLOTTER_VERSION 0.1.0)` in `plotter/CMakeLists.txt`; release tag pattern `plotter-vX.Y.Z` (packaging is plan 4).
- TDD: each task writes its failing test first. Tests run with `QT_QPA_PLATFORM=offscreen` and never need the network, a GPU, a Pi or a running n2kd unless the test says it builds and runs n2kd from this tree. Commit after each task. Each task is reviewed by an independent subagent before the next starts; the PR gets an adversarial review.
- No em-dash character anywhere: code, comments, UI strings, docs, commit messages.

## Review Focus

1. **n2kd restarts mid-session** (socket closes, reopens with a new `hello`). Expected: values go to `--` and the "No data from N2K" banner shows within 3 s, then data resumes without restarting the app; a half line at the disconnect is not parsed. Task 4.
2. **A pack directory that is half there** (manifest missing, `enc.mbtiles` missing, or directory name disagreeing with the manifest version). Expected: the pack is refused with a reason shown on the About page, the next valid pack is used, the app does not crash. Task 7.
3. **Safety depth set between two charted contours, or deeper than every contour.** Expected: safety contour snaps to the next deeper charted contour; deeper than all contours falls back to the safety depth itself (chartpack's rule); tints and soundings use the exact setting. Task 8.
4. **Power cut during track writing or settings save** (process killed between statements). Expected: database opens on restart, at most the unflushed track batch (30 s) is lost, settings are either old or new, never corrupt. Task 6 and Task 15.
5. **A settings row written by a newer app** (unknown field name in the slot JSON, unknown setting key, schema minor newer). Expected: unknown keys kept on save, unknown field names fall back to that slot's default, a newer minor opens, a newer major shows the recovery screen. Tasks 6 and 12.

**Interfaces:**
- Produces: `synth_n2k.py --canboat PATH --out FILE [--scenario everett-pt-townsend]`. Fixture contract for later tasks: path below, 20 min, own ship SA 1, three AIS targets.

The encoder is generic: for a PGN it reads `Fields` from `third_party/canboat/canboat.json` (`BitOffset`, `BitLength`, `Resolution`, `Signed`) and packs given values little-endian, unset fields as all ones (not available) except reserved fields as all ones too. Frames with payload over 8 bytes are fast packets (frame 0: `seq<<5 | 0`, total length, 6 bytes; frame n: `seq<<5 | n`, 7 bytes; pad 0xFF). CAN ID for these PDU2 PGNs: `(priority << 26) | (pgn << 8) | src`. Lines: `(%.6f) can0 %08X#%s`.

Scenario `everett-pt-townsend` (all values are what the test checks):
- Start t=1798000000.0 (2026-12-23 UTC, fixed so tests are deterministic). Own ship src 1 follows waypoints (47.9800, -122.2300) to (47.9900, -122.3000) to (48.0500, -122.4500) to (48.1100, -122.7500) at 3.0866 m/s (6 kn). 129025 and 129026 (COG true, SOG) at 1 Hz, 127250 heading = COG + 0.05 rad, reference magnetic, variation 0.2731 rad (15.65 deg E) at 1 Hz; 128267 depth at 1 Hz from `depth_m(t)`: 30 + 25*sin(2*pi*s/300) metres, offset -0.3 m, with s seconds since start; 130316 water temperature 283.15 K, instance 0, source 0 (sea), every 2 s.

- AIS: class A MMSI 367000001 (129038 position, 129794 static name "TEST TUG"), class B MMSI 367000002 (129039 position, 129809 name "TEST SAIL"), class A MMSI 367000003 position only; each reports every 10 s, src 2, positions 1 to 2 km off the own ship's track, moving at 4 to 8 kn.
